BTC Monolith

BTC Core Exam — COSIGO Dev Lab is a two-year public proof-of-concept project studying a growing Bitcoin problem: ordinary node operation is becoming slower, hotter, heavier, and less practical. The project examines Bitcoin Core bootstrap burden, pruning, AssumeUTXO snapshot loading, verification, bandwidth cost, storage cost, heat/load cost, and node survival.

The slow death of ordinary Bitcoin node operation would not happen all at once. It would happen quietly: longer sync times, more heat, more storage, more failed setups, fewer local operators, and more dependence on large infrastructure.

The problem

Bitcoin verification should remain possible for ordinary people. Yet starting a Bitcoin Core node from scratch can require days or weeks of download, validation, disk writes, heat, bandwidth, and operator patience.

If local operators disappear as the blockchain grows, independent verification drifts toward large infrastructure operators: exchanges, custodians, cloud providers, analytics companies, miners, and large holders. That is not healthy for Bitcoin.

This project is based on a simple concern: people who hold meaningful bitcoin should want ordinary node operation to remain practical. Their bitcoins depend on a network that ordinary people can still verify independently.

An urgent decentralization warning

The slow death of ordinary Bitcoin node operation would not require a protocol collapse. It would only require the ordinary user to give up.

More storage, longer initial block download, heavier validation, hotter laptops, bandwidth exhaustion, failed setups, and confusing recovery procedures can slowly push full verification away from local operators and toward large infrastructure.

A Bitcoin network where only large custodians, exchanges, cloud providers, miners, analytics companies, and wealthy operators can comfortably run serious infrastructure is not the same practical decentralization that made Bitcoin important.

What this project is

BTC Core Exam is a COSIGO development-side research and proof-of-concept project. It studies practical Bitcoin Core operation and whether verified UTXO snapshot bootstrapping can make new nodes usable faster while Bitcoin Core continues to validate history in the background.

This project does not change Bitcoin consensus. It does not replace Bitcoin Core validation. It treats snapshot providers as delivery sources, not truth authorities. Bitcoin Core must remain the verifier.

Existing technical foundation

Bitcoin Core already includes the important building blocks:

  • dumptxoutset creates a serialized UTXO snapshot.
  • loadtxoutset loads a UTXO snapshot.
  • AssumeUTXO allows a node to become usable from a verified snapshot while historical validation continues.
  • Current Bitcoin Core documentation states there is no canonical source for snapshots.

The missing piece is not merely code. The missing piece is a public, trustworthy, documented distribution and verification model.

Desired final result

  1. Document normal Bitcoin Core initial-sync cost.
  2. Document pruned-node operation and limits.
  3. Test AssumeUTXO snapshot bootstrap on clean nodes.
  4. Create manifest, checksum, and mirror-verification procedures.
  5. Compare multiple independent snapshot sources.
  6. Prove bad-file rejection behavior.
  7. Measure time, heat, CPU, bandwidth, and disk impact.
  8. Publish an operator report for wider review.

Two-year roadmap

Phase 1 — Public project setup and baseline measurements

Build the public project page, define scope, record current bcnode.io operating experience, and measure normal Bitcoin Core startup burden on ordinary hardware.

Phase 2 — Snapshot workflow lab

Test Bitcoin Core dumptxoutset, loadtxoutset, pruned-node operation, snapshot loading, and background validation behavior. Produce repeatable commands and logs.

Phase 3 — Mirror and verification model

Build a small multi-source distribution test using manifests, checksums, mirrored downloads, and independent operator confirmation. Snapshot sources should be treated as delivery trucks, not authorities.

Phase 4 — Public report and review package

Publish test results, cost estimates, failure cases, screenshots, logs, and a practical recommendation package for operators, donors, reviewers, and the wider Bitcoin community.

Why large holders should care

Bitcoin value depends on credible independent verification. If local operators fade away because node startup becomes too costly or frustrating, Bitcoin becomes easier to centralize in practice even if the protocol remains open in theory.

Major holders, miners, exchanges, custodians, wallet companies, educators, and public node operators all have a direct interest in making ordinary node operation practical.
